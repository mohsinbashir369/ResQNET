# RESQNET

RESQNET is a React/Vite dispatcher interface backed by a Spring Boot API, PostgreSQL, Redis, and Kafka.

## Run locally

1. Install Docker Desktop and Node.js 20 or later.
2. For local demo use, the protected portal credentials are `admin` / `password` for both roles. Change these before exposing the app to any shared network.
3. Put your CARTO Basemaps key in `.env` as `VITE_CARTO_API_KEY=...`; Vite reads it when the dev server starts. The `.env` file is git-ignored. CARTO requires this key on map tile requests, so browsers can see it; restrict the key to your site/referrer in CARTO's dashboard rather than treating it as a server secret.
4. Start PostgreSQL, Redis, Kafka, and the API:

   ```powershell
   docker compose up --build -d
   ```

5. In another terminal, install the frontend dependencies and start Vite:

   ```powershell
   npm install
   npm run dev
   ```

6. Open the Vite URL (usually `http://localhost:5173`). Vite proxies `/api` to Spring Boot on host port 8081 (container port 8080).

The API seeds twelve hospitals and twelve ambulances in each of the eight supported zones on startup. Flyway creates the schema. Login accounts are seeded once from environment variables; changing an account password later requires updating the user record or resetting the local database volume.

## Services and API

- `GET /api/zones/{city}/bootstrap` returns zone hospitals and ambulances; it includes recent incidents only for authenticated sessions.
- `POST /api/auth/login` returns an opaque bearer token stored in Redis with an eight-hour expiry. `POST /api/auth/logout` revokes it.
- `POST /api/zones/{city}/incidents` chooses the nearest available unit and an ICU-capable hospital, persists the incident, locks dispatch briefly in Redis, and publishes an event to Kafka topic `resqnet.events`.
- `PATCH /api/incidents/{uuid}/status` advances dispatch to transport or completion. Completing a transport releases the ambulance.
- `PATCH /api/zones/{city}/hospitals/{code}/capacity` updates ICU capacity for hospital administrators.
- `GET /api/routes` proxies driving directions, road geometry, turn steps, distance, and ETA from the configured OSRM server.
- `POST /api/zones/{city}/ambulances/{unit}/location` accepts GPS updates from an authenticated paramedic device; the dispatcher polls current positions while a dispatch is active.
- `POST /api/zones/{city}/demo/start` and `/demo/stop` (hospital administrator or paramedic session) start/stop server-side demo GPS for the selected zone. The simulator only moves units without a fresh live tracker fix, follows OSRM road geometry, and completes scene and hospital legs as dispatch status advances.
- `GET /api/zones/{city}/demo` reports whether the demo GPS scheduler is enabled for that zone.
- `GET /ws` is the authenticated STOMP WebSocket endpoint. Connect with the bearer session token in the STOMP `authorization` header, then subscribe to `/topic/zones/{city}/ambulances` for `AMBULANCE_LOCATION` updates. Updates are also published to Kafka topic `resqnet.events`.
- `GET /api/telemetry` returns recent event records from Redis; events are also published to Kafka.
- `GET /actuator/health` reports API health.

Local compose accounts when no `.env` overrides are supplied (choose the matching portal role in the sign-in dialog):

- Hospital Administrator: `admin` / `password`
- Paramedic: `admin` / `password`

These shared demo credentials are intentionally simple and must only be used locally. Set unique credentials in `.env` before any shared or deployed use. PostgreSQL stays private on the Compose network; Redis and Kafka host ports are bound to loopback. Configure TLS, managed secrets, backups, and restricted origins before deployment.

## Scope and operational limits

The API persistence, role checks, session tokens, Redis dispatch lock, Kafka event publishing, OSRM road geometry, and paramedic-device GPS endpoint are service integrations. A paramedic must open the field portal on the ambulance phone, choose its unit, grant location permission, and keep GPS sharing active for the dispatcher to receive a real device position. Until then the map animates an explicitly labelled estimate along the road route. OSRM route duration is an estimate from the road graph and does not include live traffic. The default public OSRM demo server is intended for reasonable non-commercial use; configure a self-hosted or contracted routing service for sustained or operational use. The project is not connected to emergency call systems or hospital information systems and is not suitable for real emergency dispatch without those integrations and operational validation.

Demo GPS is generated by the backend and tagged `DEMO`; it is not a real ambulance feed. Real tracker updates are tagged `LIVE` and take precedence over the simulator. After updating the code, rebuild the API with `docker compose up --build -d api` (or rebuild the full stack with the command above). Local Docker Compose enables demo GPS at startup with RESQNET_DEMO_AUTO_START=true. Set it to false in .env for a deployment using real vehicle trackers only. The public map refreshes fleet data every three seconds; signed-in clients also receive WebSocket updates. Operators can start and stop demo GPS from the map controls. Demo startup never replaces a unit registered as LIVE, even when its tracker is temporarily offline.
